# First implementation review

10 October 2026

Grist now has a working Tauri desktop application in this directory. It loads the existing Python pipeline and production files, provides a GUI text editor and media review workspace, and runs the main Claude Code CLI agents interactively in the right pane. macOS is the first tested platform; Windows compatibility is addressed in the source and still needs runtime validation.

## Implemented behavior

| Area | Current behavior |
|---|---|
| Writing setup | Two modes at the top of Step 1: source-document/folder writing and direct interactive Claude Code writing without an input file. Skill choice/edit/import and provider/model are beside them. New projects require no source; saved mode/Skill persist and carry into restarts. The existing manuscript remains available when changing setup. |
| Opening quote | Separate selectable/editable candidates before the manuscript, with a per-project inclusion switch. Switching inclusion preserves candidates/media and marks assembly for rebuilding; generation, timeline and exports use the saved flag. |
| Skills and templates | Shared source editor for writing/motion Skills, summary instructions, image/motion/cover styles, image templates and production prompts. Local Markdown/folder/ZIP imports, file/folder access, dynamic project choices, recoverable removal, history/undo, variable validation, external-edit conflicts and YAML repair. |
| Batch images | Direct generate-all and fill-missing buttons, exact static-image scope, enabled opening handling, motion exclusion, output revisions and current-input checks. |
| Project ownership | The app discovers/creates projects, saves settings, supervises jobs, tracks revisions, and flags dependent outputs for regeneration. |
| Artifact review | Manuscript editor; individual editable/selectable boxes for video titles, cover titles, cover subtitles, and opening quotes; searchable segment list; shared context editor; per-segment recording/image/video preview; opening as a separate sequence item; final landscape/3:4 videos; cover comparison and persisted selection. |
| Main step agents | Writing and motion visuals activate real Claude Code CLI in a native PTY, with xterm.js display. Source, skills, provider/model, settings, output paths, selected segments, and recording durations are prepared. The user gives instructions in the terminal. |
| Regeneration | Selected, missing, or whole-step scope where applicable; static images, saved motion rendering, and interactive motion revision are separate choices. Optional later-step rebuild guidance pauses for review. Restart creates a new production and preserves the earlier one. |
| Editing integrity | GUI JSON edits are canonical; the legacy DOCX bridge is refreshed before it is read. Optimistic hashes reject conflicting saves. History preserves earlier files. Partial regeneration retains stale markers for the remaining outputs. |
| Runtime | Authenticated local service, isolated Python job processes, media byte ranges for seeking, native terminal resizing/input/stop, process cleanup, and interrupted-session recovery. |
| API keys | Settings has a computer-wide API keys tab for the eight engine providers. Save, replace, and remove keys through native commands using macOS Keychain / Windows Credential Manager. Saved keys override CLI credentials for new jobs and stage agents; removal restores the CLI fallback. |
| Language | Settings offers English and Simplified Chinese with immediate switching and a remembered computer-wide preference. The production workspace, settings, API key controls, history, regeneration dialogs, and common errors are translated. Manuscripts, technical identifiers, and terminal output retain their original language. |
| Image providers | Image and cover settings offer Doubao, Google API key, and Google ADC, matching the CLI image registry. SiliconFlow is used by text agents only; its obsolete image option and API-key image description have been removed. |

The terminal prepares the existing stage provider rather than silently switching the project to a different account/model. Credentials come from the system store with the existing CLI environment as a fallback. Typed keys are transient masked drafts; saved values are not returned to the interface or included in project settings, history, process arguments, or launch manifests. Production keys pass to workers in their environment through the authenticated loopback service's memory. Updating a key does not interrupt a running job or terminal. Worker logs redact saved/environment key values. Claude Code's ordinary interactive trust/permission prompts remain interactive.

## Remaining release work and design limits

The Step 1 mode update passed 54 backend tests and 7 language checks. Browser inspection against an isolated engine verified top-of-step controls, direct-mode selection/save/reload, new projects without a source, and the removal of writing/source controls from production settings. Context tests verify source-mode file validation and direct-mode exclusion of former source paths while retaining the production JSON contract. Real paid writing sessions were not run.

The opening-quote update passed 57 backend tests and 7 language checks. Real offline assembly verifies that stored opening media play before the body when enabled and are skipped when disabled, in both landscape and 3:4 outputs. Browser checks verify quote selection/save, draft preservation during switching, persisted inclusion after reload, and opening sequence visibility/timing. The UI proof is `docs/opening-before-manuscript-zh.jpg`.

1. **Windows validation:** build and run on Windows, including ConPTY, native Claude installation/npm fallback, Python/FFmpeg/Node discovery, Chinese paths/fonts, media codecs, and a fresh install. The supplied CI workflow is source-check configuration, not evidence of a Windows test run.
2. **Distribution:** bundle or document Python/engine/media dependencies for a clean machine; select minimum OS/architectures; sign/notarize Mac releases and produce/test Windows installers. The current app reuses the installed CLI environment.
3. **Provider runs:** paid writing, image, voice, context, and cover generation were not exercised. Saved HyperFrames rendering is wired to the existing pinned renderer. A renderer contract test verifies that existing HTML is preserved, current narration/timing is passed, and media replacement follows a successful render; actual animated rendering still needs an integration run with a generated composition.
4. **Timeline scope:** the sequence selects segments and seeks in assembled video. Arbitrary trimming, split/merge/reorder, manual subtitle timing, and playback-driven timeline highlighting are not implemented.
5. **Agent continuity:** live sessions remain available while navigating stages; each activation currently starts a new stage-scoped session. A resume-session browser is not included. Claude Code does not manage the project.
6. **Rebuild guidance:** the guided queue is session-local. Project outputs, revisions, review markers, settings, and cover selection persist. Full automation and persistent queue recovery can be added later.
7. **Step 5 extension:** the requested future agent-and-skills editing version remains an extension alongside current assembly.

The next useful review is hands-on: inspect the existing production, try a manuscript/segment edit in a copied project, and use an interactive step agent to generate a real motion segment. That will establish the details of your preferred review layout and iteration flow without committing to a full nonlinear video editor.
